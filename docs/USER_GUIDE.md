# What2Do 使用与验收手册

## 1. 理解一条待办

一条待办有“事项”和一组“提醒”。截止时间只是记录，不会自行触发动作。

例如“交周报，周五 15:00 截止”：

| 提醒时间 | 动作 |
| --- | --- |
| 周五 14:30 | 桌面通知 |
| 周五 15:00 | 工作群钉钉 Markdown、@指定成员 |
| 周五 15:05 | 用默认浏览器打开周报页面 |

三个时间属于同一条待办；每个时间可以组合多个动作。完成这条待办后，后续未执行的提醒全部停止。

## 2. 配置大模型

打开“模型与通知”，点击“添加模型”：

- **配置名称**：你能认出的名字，例如“工作模型”“本机模型”。
- **Base URL**：服务商兼容接口的根路径，不要重复填写 `/chat/completions`。远程接口必须使用 HTTPS，本机 localhost / 127.0.0.1 / ::1 可用 HTTP。
- **模型标识**：服务商明确提供的模型 ID，不能用配置名称代替。
- **API Key**：可选，免鉴权的本机服务可以留空。

保存后测试连接。在首页对话框顶部或设置列表中选择要使用的模型。测试使用小量模型请求，可能产生提供方费用。当前适配 Chat Completions 文本响应，不支持仅提供其他协议的服务，也不保证每个模型都能可靠输出 JSON。

已有配置的密钥不会回显。编辑时留空会保留，勾选“清除”才会删除。密钥解密失败时需在原系统用户下重新填写。

## 3. 配置钉钉机器人

在目标钉钉群创建自定义机器人，取得 Webhook。当前只接受 `https://oapi.dingtalk.com/robot/send?access_token=…`。

- 如果安全设置使用**加签**，复制相应的 `SEC…` Secret。
- 如果使用**关键词**，填写相同的关键词；应用会将其放进标题和正文。
- 如果限制 IP，需要由你在钉钉配置机器实际出口 IP；桌面应用无法替你变更群安全设置。
- 默认 @ 方式可以为不 @、@所有人或指定成员。指定成员可填手机号或群成员用户 ID，多个用逗号分隔；不能只填姓名。

保存后点击“发送测试消息”。测试保留关键词和加签，但不会 @ 任何成员。真实提醒遵循渠道默认设置，或由该提醒显式覆盖。

不要把 Webhook 或 Secret 写进待办说明或对话，直接填入设置中的专用字段。

## 4. 用对话创建

示例：

> 明天下午 3 点交周报，提前半小时桌面提醒，到点再通过工作群机器人提醒，@所有人。

> 10 月 20 日晚上 8 点阅读，7 点 50 和 8 点分别桌面提醒。

> 明天上午 10 点打开 https://example.com/meeting，同时桌面提醒我开会。

系统按电脑的 IANA 时区理解“明天”等相对时间。信息不完整时会追问；完整后自动创建，右侧出现“已创建待办”，左侧显示提醒时间。**先核对列表中的绝对日期与动作**，再放心交给调度器。AI 可能理解错误，手动编辑始终可用。

每次成功创建后，待办解析的上下文会重新开始；界面仍保留该次对话。点击右上角 ↺ 可以主动开始新对话。对话不写入磁盘，退出后消失，已创建待办仍保留。换模型不会替换已创建的任务。

当前一次对话结果创建一个待办。若要求“每天/每周”，助手应说明暂不支持并询问具体日期。

## 5. 手动创建和管理

点击“新建待办”，填写标题与补充说明，在“提醒安排”下添加时间。使用“添加动作”组合桌面通知、钉钉、打开网页；钉钉可指定渠道和覆盖 @ 方式。

已执行或开始尝试的提醒会锁定为记录。后续可以新增时间；未开始的时间可以编辑、删除。修改完成后保存。使用列表搜索和进行中/已完成筛选查找待办。

点击任务左侧方框完成待办，再次恢复时，已经到期但未执行的动作会进行补发检查。删除待办会停止剩余提醒，已有执行日志保留。

## 6. 看懂执行记录

| 状态 | 意义与处理 |
| --- | --- |
| 待执行 | 尚未到期或等待调度 |
| 执行中 | 请求已被调度器领取 |
| 已提交 | 系统或钉钉确认接受请求，不代表已阅读 |
| 等待重试 | 明确失败，等待下一次自动尝试 |
| 失败 | 已达 5 次尝试上限；检查权限、网络、渠道设置 |
| 状态未知 | 超时、服务端异常或执行中断；先查看群消息/浏览器再决定重试 |
| 已跳过 | 迟到超过 15 分钟的网页动作，避免恢复电脑时突然打开旧网页 |
| 已安排重试 | 你已手动安排了新动作，旧动作保留作记录 |

手动重试会立即创建一次新的动作，保留原定时间和原始记录。可能产生重复消息，应用会要求确认。

## 7. 本机运行与安装

### 源码启动失败时

在项目根目录执行（Node.js 24 LTS，最低 22.12）：

```bash
node --version
npm ci
npm run setup
npm run doctor
npm start
```

`npm ci` 安装依赖，`setup` 另行准备 Electron 二进制；下载需要访问 GitHub Releases。如果 npm 依赖安装成功但 Electron 下载失败，应用仍然无法启动。不要使用 `--omit=dev`，桌面运行时是开发依赖。

`doctor` 会检查 Node、图形会话、Electron 依赖与二进制，完全离线，不读密钥。Linux 需要普通用户的桌面会话；服务器 SSH / 无头容器不能直接弹出窗口，也不要使用 `sudo npm start`。Windows/macOS 请在自己的桌面终端运行。

保留 `npm start` 完整报错。若已进入主进程，用户数据目录中会生成 `logs/startup.log`，记录主进程启动、窗口可见、页面桥接就绪或失败阶段。待办数据不需要删除。启动器会自动清除继承的 `ELECTRON_RUN_AS_NODE`，以免 VS Code 等工具的环境变量导致 Electron 缺少 `app` API。

首次可通过 `npm ci`、`npm start` 运行。安装包在 GitHub Actions 成功运行的 Artifacts 中，下载后解压外层 artifact ZIP，运行 `.exe` 或 `.dmg`。

当前未配置代码签名与 macOS 公证。正式分发前需要开发者证书、签名、公证和真实双平台验收。安装后的系统通知需允许权限；系统专注模式可能隐藏通知。开发模式不开启登录启动。

数据文件在 Electron `userData` 目录：

- Windows：通常 `%APPDATA%/what2do/what2do.json`。
- macOS：通常 `~/Library/Application Support/what2do/what2do.json`。

不同打包版本可能按应用名称改变目录，升级时应保持应用名和 appId 稳定。JSON 中待办内容是明文，API Key、Webhook、Secret 是系统加密后的数据。模型设置中的 API 根地址也是明文，不要在其中放令牌。导出不含模型/渠道设置；V0.1 尚无导入功能。不要直接跨设备复制加密凭据。

## 8. 第一轮验收

1. 新建一个两分钟后到期的桌面提醒；关闭窗口，确认托盘仍在；等待并检查通知与执行记录。
2. 配置钉钉，先发送不 @ 的测试消息；再在你有权限使用的群创建真实提醒，分别验证不 @、指定成员和 @所有人。
3. 新建两分钟后打开网页的动作，确认默认浏览器打开指定地址；禁止 `file:` / `javascript:` 等协议。
4. 对同一待办设两个不同时间和多个动作，确认分别执行。
5. 完成待办后确认其后续提醒停止。
6. 退出并重新打开应用，确认待办仍在且已成功动作不会重复执行。
7. 通过休眠/恢复验证通知补发；旧网页延迟超过 15 分钟应显示跳过。
8. 故意配置错误的关键词/签名，确认钉钉业务错误会记入执行记录，其他动作继续执行。
9. 配置两个模型并切换，验证缺时间的描述会追问，完整描述会自动创建。
10. 在 Windows 与 macOS 安装版分别验证系统通知权限、托盘、默认浏览器、系统密钥存储和开机启动。

自动化测试不替代使用真实模型、真实钉钉和两种操作系统的验收。未经你的配置与操作，项目测试不会向真实群发送消息。
